### API Routes

**Route 1:** `POST /api/proposals/[id]/boe/artifacts/generate`
- **Supabase role:** service_role (bypasses RLS)
- **Tenant authorization:** `resolveTenantContext()` at handler start; reject 403 if user not in proposal's tenant
- **Command:** `GenerateBOEArtifact`
- **Response:** `{ artifactId, contentHash, engineVersion, totals, conservation }`

**Route 2:** `GET /api/proposals/[id]/boe/artifacts`
- **Supabase role:** authenticated user session via `createClient()` (server)
- **RLS policy:** `boe_artifacts.tenant_id IN (SELECT get_user_tenant_ids())` — post-064, anon revoked; authenticated session required
- **Response:** `{ artifacts: [{ id, status, contentHash, generatedAt, generatedBy }] }`

**Route 3:** `GET /api/proposals/[id]/boe/artifacts/[artifactId]`
- **Supabase role:** authenticated user session via `createClient()` (server)
- **RLS policy:** same tenant-scoped policy via `get_user_tenant_ids()`
- **Response:** Full artifact row including `content` JSONB and joined `boe_citations`

**Route 4:** `POST /api/proposals/[id]/boe/artifacts/[artifactId]/supersede`
- **Supabase role:** service_role
- **Tenant authorization:** `resolveTenantContext()` check
- **Operation:** `UPDATE boe_artifacts SET status = 'superseded', superseded_at = now() WHERE id = $1`

**Route 5:** `GET /api/proposals/[id]/boe/preconditions`
- **Supabase role:** authenticated user session via `createClient()` (server)
- **RLS policy:** tenant-scoped via `get_user_tenant_ids()`
- **Returns:** `{ intelligenceConfirmed, wbsActive, scenarioApproved, citationCoverage: { total, cited } }`

**Note on auth pattern (post-migration 064):** All GET routes use authenticated user session with RLS policies scoped via `get_user_tenant_ids()`. Anonymous access was revoked in 064. This matches the pattern used in screen 1's pricing routes.

## States & Acceptance Criteria

### State 1: Pre-flight Panel

Gate checklist with four conditions:
1. Intelligence confirmed → Fix link: `?view=solicitation` (to reconfirm)
2. WBS active → Fix link: `?view=wbs-elements`
3. Scenario approved → Fix link: `?view=pricing`
4. All estimate lines cited → Shows "N uncited" count; fix link per interim behavior below

**Generate button:** Blocked-with-count when any condition unmet.

**Reuses:** `GateChecklist` from `components/shared/gate-checklist.tsx`

### State 2: CITATION_INCOMPLETE Worklist

When generation fails with `CITATION_INCOMPLETE`, render the error payload structurally:

| WBS Code | Task | Role | Period | Issue |
|----------|------|------|--------|-------|
| 1.1.2 | Requirements Analysis | Sr. Analyst | Base | No requirement links |

Each row links to fix location per **interim behavior** (see below).

### State 3: Artifact Viewer

**Viewer fetch rule:** The artifact viewer renders from ONE fetch of the stored artifact row (`content` JSONB + joined `boe_citations`). No reads of live `pricing_lines` anywhere in the viewer path. The viewer is a pure render of immutable stored data.

**Provenance header** (rendered first):
- GENERATED badge (green solid, from StatusBadge extended for 'generated')
- Content hash (truncated with copy)
- Intelligence version hash + link
- WBS version + link
- Pricing scenario + link
- Engine version
- Generated at/by
- Conservation status: "✓ Cost + Fee = Total (penny-conserved)"

**Sections** (from `artifact.content.sections`):
- WBS Estimates table
- Labor Loading Summary table
- Totals section with conservation assertion

**Per-line expandable CalcTracePanel** (approved variant):
- Reuses `CalcTracePanel` from `components/shared/calc-trace-panel.tsx`
- Props sourced from `line.calcTrace`

### State 6: Citations Walkable

Folded into the artifact viewer but listed separately per acceptance criteria:

**Citation navigation (one interaction per hop):**
1. **Estimate line → Requirement link:** Each line shows citation count badge. Click expands to show linked requirement IDs.
2. **Requirement link → Requirement:** Click requirement ID navigates to the extracted requirement (in Requirements view or inline panel).
3. **Requirement → Source quote:** The requirement displays its verbatim RFP passage (`source_text` field).

**Implementation:** Citation data comes from the same artifact fetch (`boe_citations` joined). Navigation uses existing requirement display infrastructure.

### State 4: Generation Succeeded

After successful generation:
- New artifact appears in list with GENERATED badge
- Prior artifact for same triple automatically shows SUPERSEDED (DB partial unique index enforces this)
- Viewer switches to new artifact

### State 5: Snapshot Creation (if surfaced here)

Per the brief's note that CreateProposalSnapshot may be triggered from this screen:
- Select artifacts (checkboxes)
- See composite hash preview
- Enter label (defaults to "Submission")
- Create button → snapshot locked → hash prominent

**Note:** The brief states snapshot/share management is screen 7 (separate brief). If this screen only shows snapshot creation as an entry point, we render a minimal form that hands off to the full snapshot management screen.

## Test Plan

### T1: Gate Checklist

**Setup:** Proposal with missing precondition (e.g., scenario not approved)

**Steps:**
1. Navigate to `?view=deliver-boe`
2. Verify pre-flight panel shows ✗ for unmet condition
3. Verify Generate button shows "Generate BOE — N items need resolution"
4. Click Fix link
5. Verify navigation to correct fixing screen
6. Fix condition (approve scenario)
7. Return to deliver-boe
8. Verify condition now shows ✓

**Playwright:** `tests/e2e/deliver-boe/gate-checklist.spec.ts`

### T2: CITATION_INCOMPLETE Worklist

**Setup:** Fixture proposal with all preconditions met except one WBS task lacks requirement links

**Steps:**
1. Navigate to deliver-boe (all gates pass)
2. Click Generate
3. Verify CITATION_INCOMPLETE error renders as worklist
4. Verify each uncited line shows: WBS code, task, role, period, issue
5. Click worklist row link
6. Verify navigation to WBS view (interim behavior)

**Playwright:** `tests/e2e/deliver-boe/citation-worklist.spec.ts`

### T3: Immutable Render

**Setup:** Generated artifact exists

**Steps:**
1. Navigate to artifact viewer
2. Record displayed totals, rate values
3. Via API: update pricing_lines for the scenario
4. Refresh page
5. Verify artifact viewer values unchanged (reads from stored content, not live data)

**Playwright:** `tests/e2e/deliver-boe/immutable-render.spec.ts`

### T4: Conservation Display

**Setup:** Generated artifact exists

**Steps:**
1. Navigate to artifact viewer
2. Extract displayed totals from viewer
3. Extract totals from artifact API response `content.totals`
4. Assert exact match (no recomputation drift)

**Playwright:** `tests/e2e/deliver-boe/conservation.spec.ts`

### T5: Supersede Flow

**Setup:** Generated artifact exists for a triple

**Steps:**
1. Note artifact ID and status (GENERATED)
2. Generate new artifact for same triple
3. Verify new artifact shows GENERATED
4. Verify old artifact now shows SUPERSEDED

**Playwright:** `tests/e2e/deliver-boe/supersede.spec.ts`

2. **PM-HCD fixture** (`490ea2dd`): T1 failure-path case. No prerequisites by design — demonstrates gate blocking behavior. Do NOT seed links in this branch; that's screen 3's workflow.
