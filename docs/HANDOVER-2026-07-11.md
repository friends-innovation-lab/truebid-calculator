## Safety Infrastructure Added

### 1. Remote Migration Script

**File:** `scripts/db-push-remote.sh`

All remote migrations MUST go through this script. It:
- Requires explicit `--db-url` argument
- Extracts and prints target host
- Validates against `docs/ENVIRONMENTS.md` refs
- Refuses if `supabase/.temp/` exists (linked project)
- Requires typing the project ref to confirm

**Usage:**
```bash
./scripts/db-push-remote.sh --db-url="postgresql://..."
```

### 2. Repo Never Linked

The repo must never be linked to staging or production. `supabase/.temp/` has been removed and is in `.gitignore`. If it exists, delete it before any remote operation.

### 3. Migration Coding Standards

Added to `CLAUDE.md`:
- All PL/pgSQL variables use `v_` prefix (prevents column name ambiguity)
- Any migration failure triggers whole-file audit of the bug class

### 4. Vercel Environment Fix

Production was incorrectly deploying from `develop`. Fixed:
- **Production** now deploys from `main` only
- **Preview** deploys from all other branches

## Standing Rules

1. **No `supabase link` for staging/prod** — use explicit `--db-url` via `scripts/db-push-remote.sh`
2. **No `supabase db reset` against remote** — local only, never with `--linked`
3. **No auto-confirm** — never pipe `yes` into destructive commands
4. **Migrations only** — no SQL Editor schema changes
5. **v_ prefix** — all PL/pgSQL variables in migrations
6. **Whole-file audit** — any migration failure triggers review of entire file for same bug class
