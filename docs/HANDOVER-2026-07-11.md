## Safety Infrastructure Added

### 1. Remote Migration Script

**File:** `scripts/db-push-remote.sh`

All remote migrations MUST go through this script. It:
- Requires explicit `--db-url` argument
- Extracts and prints target host
- Validates against `docs/ENVIRONMENTS.md` refs
- Refuses if `supabase/.temp/` exists (linked project)
- Requires typing the project ref to confirm

**Usage:**
```bash
./scripts/db-push-remote.sh --db-url="postgresql://..."
```

### 2. Repo Never Linked

The repo must never be linked to staging or production. `supabase/.temp/` has been removed and is in `.gitignore`. If it exists, delete it before any remote operation.

### 3. Migration Coding Standards

Added to `CLAUDE.md`:
- All PL/pgSQL variables use `v_` prefix (prevents column name ambiguity)
- Any migration failure triggers whole-file audit of the bug class

### Key Finding for Phase 4B

**Labor requirements are hints, not constraints.** The PM-HCD solicitation specifies 2 key personnel (Senior PM, HCD Lead), but the WBS correctly generated ~6 distinct roles (Product Manager, Delivery Manager, UX Researcher, Product Designer, Design Lead, Content/UX Writer). This is correct behavior — the PWS specifies minimum key personnel, but a full delivery team needs additional roles.

Phase 4B's staffing model work should:
- Distinguish between "key personnel" (contractual, must appear) and "team composition" (delivery reality)
- Use labor requirements as anchors, not as an exhaustive role list
- Ensure key personnel always appear in WBS at appropriate utilization
